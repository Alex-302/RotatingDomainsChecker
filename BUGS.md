# Исправление: Приоритет probe_text над редиректами

## Предыстория и процесс разработки

### Начальная проблема

`betist222tv.live` не определялся несмотря на наличие `const BASE_URL` в теле ответа. Браузеры и curl получали HTTP 200, а скрипт - HTTP 404.

### Диагностика

- Выполнен curl к `betist222tv.live` - обнаружен `const BASE_URL` в теле ответа
- Найден anti-debug скрипт: `disable-devtool-auto` который перенаправляет на 404 страницу
- Корень проблемы: логика проверяла JS редиректы перед `probe_text`

### Первоначальное решение

Изменен порядок проверок в `httpResolver.ts`:

1. Проверка `probe_text` → если найден, немедленный успех
2. Проверка `skip_text`  
3. Проверка JS редиректов

### Обсуждение и уточнения

**Вопрос от разработчика:** "а вспомни, почему было 'if (skipPhrase && !hasProbeText)'? Не вызовет ли это регресс где-то в другом месте?"

**Ответ:** Обнаружена потенциальная регрессия - нужно было сохранить проверку `!hasProbeText` в условии `skip_text`.

**Упрощение логики:** После проверки выяснилось, что `!hasProbeText` избыточен, так как мы выходим из функции при `hasProbeText === true`.

**Дополнительная проблема:** "а это с JS редиректами не создаст проблем?" - обнаружено что HTTP редиректы (3xx) обрабатываются ДО проверки `probe_text`.

### Финальная реализация

Модифицирован `src/httpResolver.ts` для придания `probe_text` абсолютного приоритета над всеми типами редиректов.

**Замечание о сложности:** "что-то логика адски сложная" - разработчик отметил что логика стала слишком запутанной с дублированием проверок `probe_text` в разных местах.

**Упрощение:** Вынесена проверка `probe_text` в одно место в начале цикла для всех типов ответов, что значительно упростило код.

## Ключевые изменения

### 1. Единое чтение тела ответа

- **Было**: Тело читалось отдельно для 2xx и 3xx ответов
- **Стало**: Единое чтение тела для всех типов ответов в начале

### 2. Абсолютный приоритет probe_text

```typescript
// НОВОЕ: Проверяем probe_text первым для ВСЕХ типов ответов
if (hasProbeText) {
  return success; // Выходим немедленно, игнорируем все редиректы
}

// Затем обрабатываем специфические типы ответов
if (status >= 200 && status < 300) {
  // skip_text, JS редиректы и т.д.
}
if (status >= 300 && status < 400) {
  // HTTP редиректы (probe_text уже проверен)
}
```

### 3. Порядок приоритетов

1. **probe_text** (высший приоритет - немедленный успех)
2. **skip_text** (только если нет probe_text)
3. **JS редиректы** (только если нет probe_text)
4. **HTTP редиректы** (только если нет probe_text)
