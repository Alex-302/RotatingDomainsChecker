# TODO: Умная обработка JS редиректов

## Проблема

Текущая система обрабатывает все JS редиректы одинаково, что приводит к проблемам:

- Анти-дебаг скрипты редиректят на паркованные страницы
- Сложные JS с условиями могут быть подозрительными
- Цепочечные редиректы не проверяют probe_text на промежуточных доменах

## Предлагаемое решение

### 1. Приоритезация редиректов (от простого к сложному)

```
1. HTTP редиректы (Location header) - самый надежный
2. meta refresh - простой HTML тег, почти всегда легитимный  
3. noscript редирект - фоллбэк для без-JS
4. location.replace() - простой JS редирект
5. window.location.href = - более сложный JS
6. Сложные JS с условиями/таймаутами - подозрительные
```

### 2. Детектирование "простых" скриптов

**Простые (одинаковые по длине/структуре):**

```javascript
location.replace("url")
window.location.href = "url" 
location.href = "url"
```

**Сложные (разные признаки):**

```javascript
if (condition) location.replace("url")
setTimeout(() => location.replace("url"), 1000)
function redirect() { location.replace("url") }
```

### 3. Правила приоритетизации

- **meta + noscript** → высокий приоритет (легитимные редиректы)
- **простой location.replace()** → средний приоритет
- **сложные JS с условиями** → низкий приоритет/игнорировать

## Анализ сценариев редиректов

### Сценарий А: probe_text не совпал на последнем домене

```bash
betist219tv.live → betist220tv.live → tackchen.gitee.io/404.html
```

**Что происходит:**

1. HTTP редирект на betist220tv.live (200)
2. JS редирект на tackchen.gitee.io/404.html
3. probe_text проверяется на финальном URL (404 страница)
4. probe_text не найден → failure → эвристика запускается

### Сценарий Б: антибот на последнем домене

```bash
betist219tv.live → betist220tv.live → Cloudflare challenge
```

**Что происходит:**

1. Антибот детектится на финальном домене
2. Если accept_antibot=true → success (проверка завершается)
3. Если accept_antibot=false → failure → эвристика запускается

### Сценарий В: нет пропуска антибота

```bash
betist219tv.live → betist220tv.live → Cloudflare (accept_antibot=false)
```

**Что происходит:**

1. Антибот заблокирован → failure → эвристика запускается

### Сценарий Г: эвристика если probe_text не найден

**Ответ: ДА!** После исправления в batch.ts:

```typescript
// Теперь result.success = false при probe failure
result.success = false;
result.error = "Content probe failed";
```

**Эвристика запускается** потому что `failed = !r.result.success = true`

## Проблема с цепочными редиректами

### Текущая логика

```typescript
// Проверка probe_text только на финальном домене
if (probeText && probeText.length > 0 && finalBody) {
  hasProbeText = probeText.every(text => finalBody.includes(text));
}
```

### Проблема

Если betist219tv.live легитимный, но редиректит на паркованный betist220tv.live, то:

- probe_text проверяется только на паркованном домене
- Пропускается легитимный домен в середине цепочки

### Возможное решение

Проверять probe_text на **каждом домене в цепочке**, не только на финальном.

### Дополнительная идея: Ранний выход при успешном probe_text

Если probe_text найден на промежуточном домене, немедленно использовать его как успешный результат, не продолжая цепочку редиректов. Это предотвратит попадание на парковочные страницы через подозрительные JS редиректы.

## Предложение: Умная обработка JS редиректов

### 1. Умная приоритезация

1. meta + noscript → всегда обрабатывать (высокий приоритет)
2. простой location.replace() → обрабатывать, но с осторожностью
3. сложные JS → игнорировать или помечать как подозрительные

### 2. Умная проверка probe_text

1. Проверять на каждом шагу цепочки редиректов
2. Если найден на промежуточном домене → использовать его
3. Если только на финальном → текущая логика

## Примеры из реальной жизни

### Легитимный редирект (hepbetspor)

```html
<head>
<noscript>
<META http-equiv="refresh" content="0;URL=https://hepbetspor7.cfd/">
</noscript>
<script>window.opener = null; location.replace("https://hepbetspor7.cfd/")</script>
</head>
```

- meta + noscript + простой JS
- Все указывают на один домен
- **Результат: обрабатывать**

### Подозрительный редирект (betist220tv.live)

```html
<script disable-devtool-auto md5="..." url="https://forward.pages.dev/">
<!-- огромный минифицированный анти-дебаг скрипт -->
</script>
```

- Только сложный JS с анти-дебагом
- Редирект на левый домен
- **Результат: игнорировать**

## Реализация

### Шаг 1: Детектирование типа редиректа

- Анализировать HTML контент
- Определять тип редиректа (meta, noscript, JS)
- Вычислять сложность JS

### Шаг 2: Приоритезация

- meta + noscript → высокий приоритет
- простой JS → средний приоритет
- сложный JS → низкий приоритет/игнорировать

### Шаг 3: Проверка probe_text по цепочке

- На каждом шагу редиректа проверять probe_text
- Если найден → остановиться и использовать домен
- Если нет → продолжить цепочку

### Шаг 4: Логирование

- Детально логировать типы редиректов
- Показывать приоритезацию в логах
- Помечать подозрительные редиректы
